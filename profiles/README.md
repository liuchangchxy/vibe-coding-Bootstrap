# Profiles

This directory is reserved for deliberately authored Profile records governed by `schemas/profile.schema.json`. No personal preferences are fabricated as examples in Phase 2. Profiles reference catalog IDs through default and excluded capability lists; they do not duplicate capability definitions or authorize installation.

`personal.yaml` records only explicitly stated development preferences. These preferences inform semantic review but do not override current project authority or remove safety and approval gates. Capability defaults and exclusions remain empty; preference entries do not make a Capability mandatory.

Existing Project review distinguishes asset presence from activation and authority. A Skill file proves that the Skill is available; its trigger wording and current project references determine when it applies. Historical plans do not establish current requirements.
